# Builder Profiles

Idea Forge serves three kinds of builders. Identify the profile from how the person writes and what they ask for; ask only if it's genuinely unclear ("Is this for your own business, or are you building it for a client?"). The method stays the same; language, defaults, and deliverables change.

## Business owner (no technical background)

**Signals:** describes their business and problems, not files or tools; plain language; "I just want it to work."

**Adapt:**
- Plain words: "the system" (not orchestrator), "its memory" (not brain fields), "steps it can take on its own vs. ones it checks with you" (not authority levels), "add-ons" (not components).
- More defaults, fewer questions. Offer "I'll use sensible defaults; you can change anything later."
- Show results, not structure: a short summary of what it will do each week, and the system map, rather than file trees.
- Installation steps written for a first-timer.
- Smaller wave 1 (three components) so they see a result fast.

## Consultant (building for clients)

**Signals:** mentions clients, a practice, an agency, repeatable delivery, or "my clients' businesses."

**Adapt:**
- **Client discovery mode:** turn Capture into a discovery session the consultant can run with the client, with a question set grouped by blueprint section, and a filled blueprint at the end.
- **Reusable core:** suggest separating what stays the same across clients (the method, the components) from what changes per client (the brain, voice, offers). One OS, many client brains.
- **Client handoff package** (see `os-build-test.md`).
- Neutral branding by default: the OS carries the client's or consultant's name. Idea Forge credit is optional.
- Consultants may use Idea Forge to build skills and OSes for paying clients; the license allows it.

## Power user (builds for themselves, comfortable with tools)

**Signals:** uses technical vocabulary, references files, connectors, or Claude Code; wants control.

**Adapt:**
- Use precise terms. Show `os.json` and file trees.
- Fast path: fewer confirmations, larger waves if they ask.
- Surface the scripts so they can run them directly.
- Offer the deeper tooling: skill-creator evals, subagent simulations, CI.

## Mixed or changing

People move between profiles: an owner who gets curious, or a consultant building for themselves. Follow their lead. If they start using technical terms, match them; if they ask "what does that mean?", step down. Never make the person feel tested.
